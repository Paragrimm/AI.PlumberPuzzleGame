## Tile-System

### Tile-Typen und Rotationen

| Typ | Rotationen | Verbindungen bei 0° |
|-----|------------|---------------------|
| `STRAIGHT` | 0°, 90° | oben ↔ unten |
| `CORNER` | 0°, 90°, 180°, 270° | oben ↔ rechts |
| `START` | fix (nicht drehbar) | eine Richtung |
| `END` | fix (nicht drehbar) | eine Richtung |

### Verbindungslogik

Jedes Tile hat basierend auf Typ + Rotation eine Liste von verbundenen Seiten:
- Seiten: `TOP = 0`, `RIGHT = 90`, `BOTTOM = 180`, `LEFT = 270`
- Zwei Tiles sind verbunden, wenn Tile A Seite X hat und Tile B die gegenüberliegende Seite

```gdscript
# Beispiel: corner_90 hat Verbindungen bei RIGHT (90°) und BOTTOM (180°)
# Gegenüberliegende Seiten: TOP ↔ BOTTOM, LEFT ↔ RIGHT
```

## Puzzle-Generator (Kernalgorithmus)

### Strategie: "Rückwärts-Generierung"

1. **Leeres Grid erstellen** (n × m)
2. **Gültigen Pfad generieren** (Random Walk von Start zu Ende)
3. **Tiles entlang des Pfades platzieren** (passende Typen wählen)
4. **Restliche Zellen füllen** (zufällige Tiles, die NICHT zum Pfad gehören)
5. **Tiles zufällig rotieren** (außer Start/Ende)
6. **Validieren** (Puzzle ist lösbar, Lösung ist eindeutig)

### Parameter

```gdscript
class_name PuzzleGeneratorConfig

var grid_width: int = 4
var grid_height: int = 4
var start_position: Vector2i  # Optional, sonst zufällig
var end_position: Vector2i    # Optional, sonst zufällig
var min_path_length: int      # Mindestlänge des Lösungspfads
```

## Schwierigkeitsberechnung

Dynamische Formel (nicht gespeichert):

```gdscript
func calculate_difficulty(puzzle: PuzzleDefinition) -> float:
    var base = puzzle.grid_width * puzzle.grid_height  # Grid-Größe
    var rotations = _count_required_rotations(puzzle)  # Nötige Drehungen
    var path_complexity = _calculate_path_complexity(puzzle)  # Kurven im Pfad
    
    return (base * 0.3) + (rotations * 0.5) + (path_complexity * 0.2)
```

Faktoren:
- Grid-Größe (mehr Tiles = schwerer)
- Anzahl nötiger Rotationen zur Lösung
- Pfad-Komplexität (viele Kurven = schwerer)

## Implementierungsreihenfolge

### Phase 1: Tile-Domain
1. `tile_type.gd` - Enum mit STRAIGHT, CORNER, START, END
2. `tile_definition.gd` - Custom Resource mit type + rotation
3. `tile_connection.gd` - Logik für Verbindungen pro Typ/Rotation
4. `tile.tscn` + `tile_view.gd` - Placeholder-UI mit Click-Handler

### Phase 2: Grid-Domain
5. `grid_definition.gd` - 2D-Array von TileDefinitions
6. `grid_logic.gd` - Nachbar-Ermittlung, Tile-Zugriff
7. `grid.tscn` + `grid_view.gd` - GridContainer, Tiles instanziieren

### Phase 3: Connection-Domain
8. `connection_checker.gd` - Zwei Tiles auf Verbindung prüfen
9. `path_finder.gd` - BFS von Start zu Ende

### Phase 4: Puzzle-Domain
10. `puzzle_definition.gd` - Wrapper um GridDefinition
11. `puzzle_solver.gd` - Prüft ob aktueller Zustand gelöst ist
12. `puzzle_generator.gd` - Erzeugt spielbare Puzzles
13. `puzzle_difficulty.gd` - Schwierigkeitsberechnung
14. `puzzle_validator.gd` - Prüft Generierte Puzzles

### Phase 5: Game Loop
15. `game_manager.gd` - Züge zählen, Zustand verwalten
16. `game_screen.tscn` - Layout mit Grid, Stats, Buttons
17. Click-to-Rotate implementieren
18. Win-Condition und Feedback

### Phase 6: Polish
19. `progress_tracker.gd` - Gelöste Puzzles speichern
20. `stats_display.tscn` - Züge, Verbindungen anzeigen
21. `action_buttons.tscn` - Reset, Nächstes Puzzle
22. JSON-Export (`to_json`/`from_json`) für PuzzleDefinition
